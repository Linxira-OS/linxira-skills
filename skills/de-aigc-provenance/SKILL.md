# De-AIGC Provenance

Treat provenance hygiene as a document-integrity task. Hidden characters,
container metadata, and generator fingerprints can travel with a file even when
the visible text looks correct. Clean the container deliberately, then prove
that the rewrite preserved the content that matters.

This is not an AI-detector evasion procedure. No script here estimates whether a
text was generated by a model, and no result should be described as making a
document "undetectable". Statistical watermarks and model-side provenance
signals cannot be judged from a finished file.

Format-specific limits and residual risk surfaces are in
`references/coverage.md`; scenario templates and command sequences are in
`references/workflow.md`.

## Requirements

- Python 3.9 or later, standard library only. No third-party packages,
  LibreOffice, or network access are required by the bundled scripts.
- Inputs: `.txt`, `.md`, `.markdown`, `.docx`, `.png`, `.jpg`, `.jpeg`.
- Run commands from this skill directory, or pass the full script path.
- Keep an untouched original. All cleaning writes a separate output unless
  `--in-place` is explicitly requested.

## Workflow

### 1. Discover

Scan before changing anything and keep the baseline JSON:

```bash
python scripts/scan.py manuscript.docx > scan-before.json
python scripts/scan.py manuscript.md > scan-before.json
```

`scan.py` reports invisible characters by category, code point, count, and
location, and it lists DOCX custom properties plus core author fields. Scanning
is non-destructive and exits 0 when the scan completes, even when findings
exist; the JSON summary is the review gate. Variation selectors and legitimate
full-width characters require human judgement.

### 2. Clean

Write a cleaned copy, never the only original:

```bash
python scripts/clean.py manuscript.docx --report clean.json
python scripts/clean.py manuscript.docx -o manuscript.clean.docx
python scripts/clean.py figures/ --report clean.json
```

Default outputs use a `.clean` suffix. For DOCX, `clean.py` rewrites the ZIP,
removes `docProps/custom.xml` and its content-type/relationship entries, clears
author and last-modified fields in `docProps/core.xml`, strips `w:rsid*`
attributes from the body, and removes the invisible characters from document,
header, footer, footnote, endnote, and comment parts. Styles and visible body
content are preserved.

For PNG and JPEG, `clean.py` parses container structures and removes textual
chunks and XMP payloads without re-encoding pixels. It does not remove EXIF or
other binary metadata; use a dedicated metadata tool when that is required.

### 3. Verify Fidelity

Compare the original with the cleaned result:

```bash
python scripts/fidelity.py manuscript.docx manuscript.clean.docx \
  > fidelity.json
```

`fidelity.py` extracts numbers, percentages, citation markers (`[n]`,
author-year forms, DOI, arXiv identifiers), and table references from both
sides. Missing tokens, and new tokens unless explicitly allowed, produce a
non-zero exit status. A non-zero result is a failed handoff until the difference
is explained and accepted by a human.

### 4. Report And Re-scan

Re-run `scan.py` on the cleaned output and attach both JSON reports to the
delivery record. Report residual findings, retained Unicode categories, and any
metadata that was not in scope. Never report "clean" from a single scan that
was run before the rewrite.

## Interpretation Rules

- Remove zero-width characters, bidirectional controls, BOMs, and soft hyphens
  from prose. Keep U+3000 and full-width punctuation; they are typographic
  characters, not hidden content.
- Report variation selectors (U+FE00–FE0F, U+E0100–E01EF) but do not delete
  them automatically. They may be part of emoji or CJK sequences. Deletion is
  an explicit editorial decision.
- Preserve line endings, spelling, numbers, units, symbols, and citation text
  during text cleaning. Any content edit belongs to the author, not this skill.
- Treat a cleaner output as a new artifact. Record what changed in JSON, not in
  the manuscript itself.

## Boundaries

- Statistical watermark detection or removal is out of scope. It cannot be
  decided from a single document without provider-side information and a
  controlled sampling design.
- PDF metadata, annotations, incremental revisions, embedded files, and
  object streams need external tools; this skill does not claim to clean PDFs.
- DOCX cleaning is not exhaustive. Tracked changes, comments, embedded
  objects, document properties outside the listed fields, and thumbnail images
  may still carry identity or generator traces. Inspect them manually.
- PNG/JPEG cleaning removes text and XMP blocks only. EXIF, GPS, ICC, and
  proprietary application segments may remain.
- Never use this skill to misrepresent authorship, hide undisclosed AI use
  where disclosure is required, or defeat institutional review. Follow the
  applicable journal, funder, and institutional policy.
- The scripts report observable bytes and structure. They do not certify
  originality, truthfulness, or compliance.

## Completion Criteria

- Baseline and post-clean scan reports are stored.
- The cleaned artifact is separate from the original unless in-place cleaning
  was explicitly approved.
- `fidelity.py` exits 0, or every difference is reported and accepted by a
  reviewer.
- Residual invisible characters, retained variation selectors, and unsupported
  metadata are listed in the handoff record.
- The final statement distinguishes deterministic cleanup from unverifiable
  provenance claims.
